06 / Implementation boundaries

Use the guide to learn; use the source to reproduce

This visual guide explains the structure and read order, but it does not reproduce every normative table, polynomial, coordinate, bit-width rule or edge case needed to build a conforming encoder. The links below show where this generator implements those details. They are readable implementation references, not replacements for ISO/IEC 18004.

Modes, count widths and block tablesconstants.js defines mode indicators, the alphanumeric alphabet, character-count widths, EC-level format values, EC codewords per block and block counts for versions 1–40. Encoding unitssegment.js validates and converts Numeric, Alphanumeric, UTF-8 Byte and Shift JIS Kanji units into payload bits. Mixed-mode optimizationsegment-optimizer.js finds a low-cost sequence of Numeric, Alphanumeric and Byte segments, including each repeated mode and count header. Version and data codewordssegments.js selects a fitting version and writes segment headers, payload, terminator, byte alignment and alternating pad words. Capacity and remainder geometrycapacity.js calculates raw data modules, character-count widths and usable data codewords from version, recovery level and block structure. Reed-Solomon and interleavingreed-solomon.js contains GF(256) multiplication, generator-divisor construction, remainder generation, short/long block division and data/EC interleaving. Matrix, metadata and placementmatrix-encoder.js places functional patterns, writes BCH-protected metadata, traverses codeword bits and produces each mask candidate. Eight mask formulasmask.js gives the exact row/column predicate used by every mask candidate. Mask penalty scoringpenalty.js scores runs, blocks, finder-like sequences and dark/light imbalance to select the automatic mask. Shift JIS Kanji conversionkanji.js builds the browser-supported Shift JIS map, validates the two QR Kanji ranges and transforms characters into 13-bit values. Structural and capacity teststests/qr/qr.test.js exercises versions, modes, capacities, masks, codewords and expected matrices. Reference parity harnesstests/helpers/qr-parity.js compares each split parity range against an optional node-qrcode reference bundle.
Not implemented by this encoder

The current source targets standard Model 2 QR Codes in Numeric, Alphanumeric, Byte and manually selected Kanji modes. It is not an implementation reference for ECI segments, Structured Append, FNC1/GS1, Hanzi mode, Micro QR, Rectangular Micro QR, Model 1 symbols or QR decoding. Consult the applicable normative specification before claiming compatibility beyond the tested scope.
